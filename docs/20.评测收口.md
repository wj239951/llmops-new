## 2. 基线（183 题）

`python -m eval run --set bank --modes dense,hybrid,rerank --out eval_results/baseline_bank`：

| 模式 | Recall@6 | MRR | 命中率 | 覆盖率 | 误放行 | P50 | P95 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| dense | 100% | 0.8992 | 97.97% | 100% | 71.43% | 40 ms | 48 ms |
| hybrid | 100% | 0.888 | **99.32%** | 100% | 74.29% | 51 ms | 83 ms |
| rerank | 100% | 0.888 | 96.62% | 96.62% | **2.86%** | 472 ms | 618 ms |

两个可读的点：

1. **混合检索在 196 篇语料上确实提高了命中率**（97.97% → 99.32%），但 MRR 略降（0.8992 → 0.888）——BM25 把精确命中的片段排上来，同时也会把部分语义题的正确片段往后推。
2. **精排的代价被量化了**：命中率 −1.35pp、P95 从 48 ms 涨到 618 ms，换来误放行 74% → 2.86%。

这份基线的意义不是数字好看，而是**以后每次改检索参数，都能用一条命令判断是不是退化了**。

## 3. 怎么用

```bash
cd llmops-backend

# 1) 只校验题库格式（CI 在跑这个，不连数据库）
python -m eval check

# 2) 跑评测 + 对比基线，退化则退出码 1
python -m eval run --set bank --modes dense,hybrid,rerank \
  --gate eval_results/baseline_bank/summary.json --out eval_results/ci

# 3) 只要对比两份已有结果
python -m eval gate --baseline eval_results/baseline_bank/summary.json \
  --current eval_results/ci/summary.json

# 4) 端到端拒答评测（需要 Ollama + 精排；约 4 分钟）
python -m eval e2e --limit 5
```

门禁阈值默认是「命中率下降 ≤ 2pp、误放行上升 ≤ 5pp」，可用 `--max-hit-drop` / `--max-fa-rise` 调。

## 4. 顺带清理

`eval/runner.py`、`app/services/query_rewrite.py`、`tests/test_query_rewrite.py`、`tests/test_rag_search.py`、
`tests/test_rerank_toggle.py` 五个文件带 UTF-8 BOM（编辑器写出的），一并去掉，避免 diff 噪音。

## 5. 局限与下一步

1. **20 段多轮还没进 harness**：它的结构是「会话段」而不是「单题」，需要给 `eval` 加 `multiturn` 子命令（复用 docs/14 的 off/rule 对照）。这是下一步。
2. **e2e 不在 CI 里**：需要 Ollama + 精排，只能在本地/自建 runner 跑；`check` 只保证格式。
3. **门禁仍靠手动**：GitHub 托管 runner 跑不了检索评测，`rag-eval-gate` 那段仍是注释。要真正挡退化，得接自建 runner 或把 `--gate` 串进发布脚本。
