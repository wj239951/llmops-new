# 21. 多模态结构蒸馏实验（图 → 结构化 Markdown）

> 时间：2026-11-18 ｜ 基座：Qwen3.5-0.8B-TextPreprocessor（已蒸馏的文本清洗模型）
> 目标：让这个「只洗文本」的模型学会看懂文档版面，输出带标题层级与表格的 Markdown

---

## 1. 为什么做这件事

`Qwen3.5-0.8B-TextPreprocessor` 的底座是原生多模态的 Qwen3.5-0.8B，但微调只动了语言侧，
视觉塔一直没用上。如果能直接「看图 → 输出结构化 Markdown」，就能把扫描件、设备铭牌、
巡检表直接喂进 RAG 知识库，省掉独立的 OCR + 版面分析链路。

先测了基线（未训结构）在 OmniDocBench 30 页中文子集上的表现：

| 指标 | 基线 | 专用 OCR 模型（0.8–1.3B） |
|---|---|---|
| Text Edit ↓ | 0.2838 | 0.0244 – 0.0326 |
| Table TEDS ↑ | 0.1069 | 91 – 93 |
| Reading Order Edit ↓ | 0.3365 | 0.02 量级 |

**认字能力够用（约 72% 字符正确），结构能力基本为零**——表格 TEDS 只有 10.69，
阅读顺序也乱。这个结论决定了：要补的是「结构」，不是「认字」。

---

## 2. 实验设置

### 2.1 训练

| 项 | 配置 |
|---|---|
| 方法 | LoRA（r=8, alpha=16, dropout=0.05），视觉塔冻结 |
| 目标模块 | q/k/v/o/gate/up/down_proj（语言侧，3.19M 参数，占 0.37%） |
| 精度 | bf16 + gradient checkpointing |
| 图像 | 长边缩放到 √max_pixels，避免整页高分辨率撑爆显存 |
| 显存 | 峰值 **1.8 GB**（A4 页降到 900k 像素 / 2048 序列） |

> 踩坑：整页 2M 像素 / 4096 序列在 24GB 卡上会 OOM（激活吃到 22GB）；
> 降到 900k / 2048 后稳定在 1.8GB，且效果更好——分辨率不是越高越好，要和显存匹配。

### 2.2 数据

三轮的数据构成完全不同，这是理解结果的关键：

| 轮次 | 数据 | 样本数 | 表格页占比 | 来源 |
|---|---|---|---|---|
| v1 | OmniDocBench 中文 | 318 | ~60% | 真实 |
| v2 | + 合成页面（模板渲染） | 1,903 | **76%** | 含 1,200 合成 |
| v3 | MarathonDocBench + OmniDocBench | 3,791 | **8%** | 全真实 |

### 2.3 评测

OmniDocBench 官方评测器（Docker 镜像 `ghcr.io/zeng-weijun/omnidocbench-eval`），
固定 30 页中文子集，指标：Text Edit（文字），TEDS（表格结构），Reading Order（阅读顺序）。

---

## 3. 结果

### 3.1 主指标（四轮 + OCR 基线）

| 指标 | 基线 | v1（318） | v2（1903） | v3（3791 真实） | OCR 两段式 |
|---|---|---|---|---|---|
| **Table TEDS ↑** | 0.1069 | 0.1741 | **0.2307** | 0.0477 | 0.0000 |
| **Text Edit ↓** | **0.2838** | 0.3401 | 0.3611 | 0.4201 | 0.5121 |
| **Reading Order ↓** | **0.3365** | 0.3983 | 0.4122 | 0.5209 | 0.4798 |

> OCR 两段式 = RapidOCR 读字 + 行聚类排序，**不产出表格**，所以 TEDS 为 0。
> 端到端方案在结构上明显优于朴素 OCR，但在文字保真度上不如未微调的基线。

### 3.2 分版面 Text Edit

| 版面 | 基线 | v1 | v2 | v3 |
|---|---|---|---|---|
| 杂志 magazine | 0.2290 | 0.1007 | 0.0166 | **0.0064** |
| 报表 research_report | 0.0015 | 0.1986 | 0.0360 | **0.0020** |
| 试卷 exam_paper | 0.1454 | 0.2426 | **0.1556** | 0.3107 |
| 书 book | 0.3123 | 0.3926 | 0.4118 | 0.5088 |
| 教材 colorful_textbook | 0.4071 | 0.4220 | 0.7826 | **0.8641** |
| 报纸 newspaper | 0.8071 | 0.9759 | 0.9452 | 0.9577 |

### 3.3 清洗能力回归（副作用检查）

结构 adapter 是**加在清洗模型上的**，必须确认没有把原能力练坏。
测试集：rule/test（50 条）、teacher/test（40 条），指标沿用原项目定义。

| 数据集 | 基线 | v1（未混清洗） | v2（混 15%） |
|---|---|---|---|
| rule 完全一致 | 92.0% | 90.0% | **96.0%** |
| teacher 完全一致 | 87.5% | **80.0%** | **85.0%** |
| 新增率（rule） | 0.005 | 0.005 | 0.010 |

**结论：不混清洗数据会遗忘（teacher 87.5→80），混 15% 能保住甚至反超（rule 92→96）。**

---

## 4. 失败分析：v3 为什么垮了

v3 的数据最多（3,791 条真实页），但 TEDS 从 0.231 崩到 0.048。原因不是「数据不够」，而是**分布错配**：

1. **表格页占比从 76% 掉到 8%**
   MarathonDocBench 是书籍/报告正文数据集，3,088 页里只有 300 页带表格。
   模型被大量纯文本页训练成「只输出文字、不画表格」。

2. **短页教坏了输出长度**
   Marathon 含目录页、扉页，目标只有几十字。推理时 30 页里有 **6 页只输出 8–29 个字符**
   （v2 在同样页面能输出上千字）。

3. **纯文本页确实变得更准了**
   杂志 0.017→0.006、报表 0.036→0.002——说明真实文本页对「纯文字排版」是有效的，
   只是比例失控把表格能力挤掉了。

**一句话：能力不是随数据量线性增长的，而是随「与任务相关的样本比例」增长的。**

---

## 5. 三条被验证的规律

1. **表格能力由表格页比例决定**，不是数据总量。v2（76% 表格页）TEDS 0.231，
   v3（8% 表格页）只有 0.048。
2. **混训能保住旧能力**：15% 清洗数据让 rule 一致率从 92% 涨到 96%。
3. **分辨率要和显存匹配**：900k 像素 / 2048 序列是 6–24GB 显存的甜点区；
   整页 2M/4096 在 24GB 上会 OOM，而且效果未必更好。

## 7. 复现

```bash
# 训练（3090，约 40 分钟 / 3,800 步）
python train_mixed.py --data merged_v3.json --model-dir ./model --out ./adapter_v3 \
  --epochs 1 --lr 5e-5 --max-pixels 900000 --maxlen 2048

# 推理 30 页
python infer_eval.py --adapter ./adapter_v3 --out ./pred_v3

# 官方评测
docker run --rm \
  -v gt_30.json:/workspace/gt/gt.json:ro \
  -v pred_v3:/workspace/data_md/predictions:ro \
  -v config:/workspace/configs:ro \
  -v result:/workspace/result \
  ghcr.io/zeng-weijun/omnidocbench-eval:repro-ubuntu2204 --config configs/custom.yaml

# 清洗回归
python eval_clean.py     # 基线 vs adapter 对比
```

### 脚本清单

| 文件 | 作用 |
|---|---|
| `train_mixed.py` | 图像 + 文本混训（LoRA） |
| `infer_eval.py` | 30 页推理，输出 `.md` |
| `eval_clean.py` | 清洗能力回归（rule/teacher 测试集） |
| `ocr_baseline.py` | RapidOCR 两段式基线 |
| `marathon_to_jsonl.py` | MarathonDocBench → 训练 JSONL |
| `synth_pages_v3.py` | 合成页面生成（模板渲染 + 自动真值） |

### 环境

torch 2.7.1+cu126 / transformers 5.23.0 / peft 0.21.3 / Python 3.12
（transformers 5.x 要求 torch ≥ 2.6；缺 torchvision 时需绕过 AutoProcessor 的视频处理器校验）

---

## 8. 结论

- **结构蒸馏这条路成立**：TEDS 从 0.107 提升到 0.231（+116%），且清洗能力未受损。
- **但代价是文字保真度**：Text Edit 0.284 → 0.361，主要来自「纯文本页被过度结构化」。
- **数据配比比数据量更重要**：v3 样本最多但最差。
- **距离专用 OCR 模型仍有数量级差距**（TEDS 0.23 vs 92），
  但已经证明「0.8B 通用模型 + 少量数据」能学到版面结构，这条路值得继续。

### 发布时踩的坑（便于下次复用）

| 现象 | 原因 | 解决 |
|---|---|---|
| ModelScope SDK `PermissionError: ~/.modelscope/credentials` | 无法写用户目录 | 跳过 cookie 落盘 + `USERPROFILE` 指向可写目录 |
