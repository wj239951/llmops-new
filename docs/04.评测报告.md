# RAG 检索层评测报告

- 日期：2026-11-04
- 评测对象：`app/services/rag_service.py`（检索）与 `app/services/chat_service.py`（`rag_status` 判定）
- 语料：`mysql-init/llmops_db.sql` 中的 11 篇工业知识文档，重建后 21 条向量
- 题库：`experiments/eval_qa.jsonl`（45 条）
- 脚本：`llmops-backend/tools/evaluate_rag.py`
- 结果：`experiments/results/`

## 1. 背景与目标

README 旧版声称「31 行阈值 × 6 指标扫描标定 0.53」「12 组实验验证稳定性」，但仓库里没有对应的题库、脚本和原始结果，这些数字无法复现。本次把评测固化成了「题库 + 脚本 + 结果」三件套，用来回答两个问题：

1. 当前配置（`RAG_SCORE_THRESHOLD=0.53`、`RAG_WEAK_MARGIN=0.06`、`RAG_CANDIDATE_K=6`、`RAG_FEED_TOPK=3`）在固定题库上的检索表现到底如何；
2. 阈值与弱命中余量是否还有可标定空间。

本次只评测**检索层**，不调用对话模型。端到端「模型是否拒答」不在范围内，原因见第 8 节。

## 2. 评测集设计

`experiments/eval_qa.jsonl` 每行一道题，字段：

| 字段 | 说明 |
| --- | --- |
| `id` | `q01`–`q45` |
| `type` | `exact` / `paraphrase` / `no_answer_far` / `no_answer_near` |
| `question` | 用户问法 |
| `expected_doc_ids` | 正确文档在 MySQL 中的主键（44、46–55），无答案题为 `[]` |
| `reference_answer` | 人工参考答案，供人工判断 |
| `note` | 备注（近域无答案题标注了「正域但知识库无答案」） |

| 类型 | 数量 | 说明 |
| --- | --- | --- |
| `exact` | 21 | 尽量使用文档原词提问（型号、数值、周期） |
| `paraphrase` | 16 | 同义改写、口语化问法，考察语义检索而非关键词匹配 |
| `no_answer_far` | 4 | 与知识库无关：年假天数、叉车证、废水 COD、IT 备份周期 |
| `no_answer_near` | 4 | 与知识库同领域但文档未写：健康证有效期、E-073 传感器型号、变频器载波频率、灭火器报废年限 |

45 条题覆盖全部 11 篇文档，其中 37 条可回答、8 条无答案。注意：`no_answer_near` 是最容易「误接受」的一类问题，因为它们的向量与相关文档非常接近。

## 3. 方法

评测流程与线上检索保持一致：

```
问题 → bge-m3 向量化 → Chroma cosine 检索 top-6（RAG_CANDIDATE_K）
     → 按阈值过滤（score >= 0.53） → 截断到 top-3（RAG_FEED_TOPK）
```

指标定义：

| 指标 | 定义 | 期望 |
| --- | --- | --- |
| recall@6 | 正确文档是否出现在 6 条原始候选中 | 越高越好 |
| MRR | 正确文档在原始候选中首次出现排名的倒数 | 越接近 1 越好 |
| coverage | 阈值过滤后是否还有片段可喂给模型（仅可回答题） | 100% 最好 |
| hit@3 | 正确文档是否进入最终喂给模型的 3 条片段 | 100% 最好 |
| top1 准确率 | 最终片段第一条是否来自正确文档 | 100% 最好 |
| 无答案误接受率 | 无答案题过滤后仍喂了片段给模型的比例（far / near / all） | 越低越好 |

`score = 1 - cosine_distance`，与 `RAGService.search()` 中的换算一致（`rag_service.py:151-169`）。

## 4. 基线结果

当前配置下（threshold=0.53、margin=0.06、K=6、feed=3、21 条向量，跑一次约 1.6 秒）：

| 指标 | 数值 |
| --- | --- |
| 可回答题 / 无答案题 | 37 / 8 |
| recall@6 | **100%**（37/37） |
| MRR | **1.0000** |
| coverage | **100%**（37/37） |
| hit@3 | **100%**（37/37） |
| top1 准确率 | **100%**（37/37） |
| 无答案误接受率（far） | **100%**（4/4） |
| 无答案误接受率（near） | **100%**（4/4） |
| 无答案误接受率（all） | **100%**（8/8） |
| 正确命中 top1 最低分 | 0.5808 |
| 可回答 top1 中位数 / 均值 | 0.6641 / 0.6586 |
| 无答案 top1 最高分 / 均值 | 0.6790 / 0.5954 |

解读：这批中文工业语料的**召回质量本身很好**——37 条可回答题的 top1 全部正确，MRR 为 1.0。问题出在「无答案 / 近域问题」：8 条无答案题全部越过了 0.53 阈值，被当作正常知识片段喂给了模型。

## 5. 阈值扫描（0.30–0.80，步长 0.01）

`experiments/results/threshold_sweep.csv` 共 51 行。摘录 0.50–0.65：

| 阈值 | coverage | hit@3 | top1 准确率 | 误接受(all) | far | near | balanced accuracy |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0.50 | 100% | 100% | 100% | 100% | 100% | 100% | 50.00% |
| 0.53（当前） | 100% | 100% | 100% | 100% | 100% | 100% | 50.00% |
| 0.54 | 100% | 100% | 100% | 75.00% | 50% | 100% | 62.50% |
| 0.55 | 100% | 100% | 100% | 75.00% | 50% | 100% | 62.50% |
| 0.56 | 100% | 100% | 100% | 62.50% | 50% | 75% | 68.75% |
| 0.57 | 100% | 100% | 100% | 62.50% | 50% | 75% | 68.75% |
| **0.58** | **100%** | **100%** | **100%** | **50.00%** | **25%** | **75%** | **75.00%** |
| 0.59 | 91.89% | 91.89% | 91.89% | 50.00% | 25% | 75% | 70.95% |
| 0.60 | 89.19% | 89.19% | 89.19% | 50.00% | 25% | 75% | 69.59% |
| 0.61 | 81.08% | 81.08% | 81.08% | 37.50% | 0% | 75% | 71.79% |
| 0.65 | 54.05% | 54.05% | 54.05% | 25.00% | 0% | 50% | 64.53% |

结论：

- 单一阈值下，**不存在**同时满足「hit@3 ≥ 85% 且误接受 ≤ 20%」的稳定区间（脚本输出的 `stable_threshold_range` 为 `null`）。
- 平衡准确率最高的是 0.58（75%）：保住 100% 召回的同时把误接受从 8/8 降到 4/8；但 0.59 就开始丢正确片段（覆盖率降到 91.89%）。
- 「不丢任何正确片段」的最大阈值就是 0.58，而最小正确 top1 是 0.5808——只有 **0.0008** 的余量，属于刀刃平衡，换问法或换语料就可能失效。因此不建议把默认阈值改成 0.58。

## 6. 弱命中余量扫描（0.00–0.15，步长 0.01）

`experiments/results/margin_sweep.csv` 基于当前阈值 0.53。关键数字：

| margin | hit 带占比 | weak 带占比 | 正确命中被降级 | Youden J |
| --- | --- | --- | --- | --- |
| 0.00–0.05 | 100% | 0% | 0% | 0% |
| 0.06（当前） | 91.89% | 8.11% | 8.11%（3/37） | -8.11% |
| 0.08 | 81.08% | 18.92% | 18.92% | -18.92% |
| 0.10 | 67.57% | 32.43% | 32.43% | -32.43% |
| 0.15 | 35.14% | 64.86% | 64.86% | -64.86% |

解读：

- 题库中**没有「错误 top1」样本**（37 条可回答题 top1 全对，无答案题按定义没有正确文档），因此余量在当前题库上**无法标定**：沿任何方向调整都没有「把错误从 hit 带挪进 weak 带」的收益，增大余量只会把正确命中降级。
- 当前 0.06 会把 3/37 = **8.11%** 的正确命中标成 `weak_hit`。这只影响前端提示，不影响实际喂给模型的片段（片段照常进入上下文）。
- 0.00–0.05 在本题库上与 0 余量等价（所有 top1 都 ≥ 0.58 ≥ 0.53+0.05）。但不建议据此把 0.06 改成 0.05：0.05 恰好卡在最小正确分 0.5808 之下 0.0008，同样是刀刃平衡。

## 7. 分数重叠与端到端抽查

正确题与无答案题的 top1 分数分布**重叠**：

- 正确题 top1 范围：0.5808 – 0.7602（中位数 0.6641）
- 无答案题 top1 范围：0.5329 – 0.6790（均值 0.5954）
- 重叠区间：**0.5808 – 0.6790**

也就是说，仅凭 top1 cosine 分数，无法把「真正命中」和「近域但无答案」可靠分开。这是单阈值方案的原理性上限，不是调参能解决的。

端到端抽查（`POST /api/chat`，`use_rag=true`，本地 Ollama `deepseek-r1:7b`）：

| 项 | 结果 |
| --- | --- |
| 问题 | 注塑机 ZX-2026 的螺杆传动链条必须使用什么型号的润滑脂？ |
| top1 | 0.5808（`01_注塑机ZX-2026巡检手册.txt`） |
| rag_status | `weak_hit`（0.5808 < 0.53 + 0.06 = 0.59） |
| sources | 1 条，含「RL-2077」原文片段 |
| answer | 注塑机 ZX-2026 的螺杆传动链条必须使用型号为 RL-2077 的润滑脂。 |
| 耗时 / token | 17.8s / 635 tokens |

这条抽查同时说明了三件事：检索链路是通的、答案有知识库依据；但当前 0.06 余量会把一个**正确答案**标成 `weak_hit`，与第 6 节 8.11% 的统计一致。

## 8. 局限

1. **只测检索层，不测生成**：`chat_service.py` 拼给模型的提示词是「如果知识库内容不足，请说明不足，再结合通用知识补充」，模型不会硬拒答。因此「检索层误接受」不等于「最终回答错误」，端到端拒答率需要另做生成评测。
2. **题库规模有限**：45 条合成题、11 篇语料、8 条无答案问题；每类无答案题只有 4 条，far/near 的百分比粒度是 25%。
3. **单语料、单向量空间**：只在当前 `knowledge_bge_m3` collection 上评测，未验证换语料后的阈值稳定性。
4. **阈值扫描粒度 0.01**：真实最优阈值的小数位可能更细，但样本量不足以支撑更细的标定。
5. `per_query.csv` 中「正确排名」按「同篇文档多 chunk 只算首次命中」处理；若正确文档有 2 个 chunk，命中任一即算对。

## 9. 结论与建议

1. **阈值保持 0.53 作为默认值**：它最大化召回（37/37），符合当前「宁可多喂片段、让模型自己判断」的产品取向。0.58 虽然平衡准确率更高，但只比最小正确分高 0.0008，不适合写死。
2. **弱命中余量暂保持 0.06**：本题库无法标定余量的价值；0.06 的代价是 8.11% 正确命中被标 `weak_hit`。等有了「错误 top1」的 hard-negative 样本，或接入 rerank 的分数后，再重新标定。
3. **单阈值无法解决拒答**：正确/无答案分数重叠是原理性问题，下一步应做 rerank 精排（交叉编码器），或用模型侧拒答策略兜底，而不是继续在 cosine 阈值上找数字。
4. **交付物**：题库、脚本、扫描结果已入库，任何人可复现本报告；后续改动阈值/余量应同步重跑并更新本报告。
