# 22. 图片输入接入（用户发图 → OCR → 合并提问 → RAG）

> 时间：2026-11-19 ｜ 改动：后端 `app/services/image_input.py`、前端 ChatStudio 上传区

---

## 1. 需求

用户会在对话框里直接发图片（设备铭牌、报错截图、巡检表单照片），期望：

```
图片 + 文字提问  →  读出图片内容  →  与提问合并  →  走原有 RAG 检索  →  回答
```

**不需要**整页文档解析（表格结构、阅读顺序、Markdown 层级），只需要把图里的字读准。

---

## 2. 方案选型（实测）

在 3 张模拟用户图上对比了三条路线（字符准确率 = 1 - 编辑距离，空白已归一化）：

| 图片 | 基线 TextPreprocessor | +结构 adapter_v2 | **RapidOCR** |
|---|---|---|---|
| 设备铭牌 | 0.912 | 0.912 | **0.947** |
| 报错截图 | 1.000 | 1.000 | 1.000 |
| 巡检表单 | 0.962 | 1.000 | 0.962 |
| **平均** | 0.958 | 0.971 | **0.970** |
| 速度 | 3–37 s（GPU） | 10–37 s（GPU） | **~2 s（CPU）** |

准确率接近，但看输出质量差别很大：

- **adapter_v2 会把铭牌硬套成 `<table>`**，还会把 `1200 kN` 读成 `2000kN`、`ZX-1200` 读成 `ZX-12200`（重复输出）
- **基线会拆字加空格**（`Z X - 1 2 0 0`），铭牌末尾还会截断；换更强的提示词反而触发重复退化（输出 `1 2 3 4 ...`）
- **OCR 输出干净的行文本，零幻觉**

**结论：选 OCR。** 之前三轮结构蒸馏的价值在整页文档解析，不适用于「用户随手发图」。

## 3. 实现

### 3.1 请求 / 响应

新增请求字段（`app/schemas/chat.py`）：

```python
image_base64: str | None   # data:image/png;base64,... 或裸 base64
```

响应新增（`ChatResponse` / SSE 的 `meta`、`done`）：

```json
"image": {"engine": "rapidocr", "chars": 67, "ms": 2071, "truncated": false, "text": "…前 500 字"}
```

### 3.2 处理流程（`app/services/image_input.py`）

```
base64 → 解码（≤8MB）
      → OCR（长边缩到 2000，避免大图吃内存）
      → 置信度过滤（<0.5 丢弃）
      → 行聚合（中心 y 相近归一行，行内按 x）
      → 整理（空白压缩、空行去除、相邻重复行去重）
      → 截断到 1500 字
      → merge_query(图片文字, 清洗后的提问) = "图片文字\n\n提问"
```

图片文字**在前**：给检索提供上下文，用户提问**在后**：决定检索意图。

### 3.3 与清洗的关系

顺序是**先清洗提问、再合并**：

```python
clean_query, clean_meta = self._clean_query(req)          # 原有逻辑不动
image_meta = extract_image_text(req.image_base64)         # 新增
final_query = merge_query(image_meta["text"], clean_query)
```

`final_query` 同时用于检索与 LLM 提问；用户原文仍按 `req.query` 写库。

### 3.4 降级

图片通道**全部失败都不影响聊天**：

| 情况 | 行为 |
|---|---|
| 没装 `rapidocr_onnxruntime` | 记一条 warning，`applied=false`，按纯文本处理 |
| base64 非法 / 超过 8MB | `reason=invalid_image`，忽略图片 |
| OCR 异常 | `reason=ocr_error: …`，忽略图片 |
| 图里没字 | `reason=no_text`，忽略图片 |
| 识别文本超 1500 字 | 截断并置 `truncated=true` |

### 3.5 配置项（`app/core/config.py`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `IMAGE_INPUT_ENABLED` | `true` | 总开关 |
| `IMAGE_INPUT_MAX_BYTES` | `8388608` | 单图上限（解码后） |
| `IMAGE_INPUT_MAX_CHARS` | `1500` | 提取文本上限 |
| `IMAGE_INPUT_MIN_SCORE` | `0.5` | OCR 置信度阈值 |

### 3.6 前端（`ChatStudio.vue`）

- 「用户输入」下方新增「图片（可选）」：选择图片 → 本地预览文件名 → 移除
- 发送时把 `FileReader` 读出的 data URI 放进 `image_base64`
- 收到 `meta` / `done` 后显示「已识别 N 字（X ms）」
- 前端限制 8MB，超限直接提示

## 5. 已知限制

1. **OCR 对复杂版式仍会串行**：表格多列时行内顺序可能错（`检查项 标准` 丢了一列）
2. **合成图偏乐观**：当前 3 张样本是渲染出来的，真实手机照片（反光、倾斜、模糊）需要重新测
3. **单图只取文本**：不解析表格结构、不保留版面位置
4. **CPU 推理约 2 秒**：首张图有模型加载开销（约 0.5 秒额外）
