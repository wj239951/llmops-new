# 23. 输入清洗通道与 GPU 隔离

> 2026-11-19 ｜ 结论：6 GB 显存放不下「清洗模型 + embedding」，用 CPU 跑 embedding 解决

---

## 1. 问题

开启「精细清洗」后，后端日志：

```
输入清洗失败（mode=model），按 rule 回退: HTTPConnectionPool(host='127.0.0.1', port=8010): Connection refused
```

8010 是 `tools/clean_server.py`（Qwen3.5-0.8B-TextPreprocessor）。起不来时会自动回退规则清洗，不影响主链路。

## 2. 根因：显存装不下两个模型

| 组件 | 占用 |
|---|---|
| 清洗模型（fp16，0.8B） | ~1.6 GB 显存 |
| Ollama `bge-m3` embedding | ~3.8 GB 显存 |
| 合计 | **> 6 GB**（显卡只有 6 GB） |

实测：清洗服务一上 GPU，Ollama 的 embedding 立刻 OOM，**所有 RAG 请求返回 500**：

```
llama-server process has terminated: cudaMalloc failed: out of memory
ggml_backend_buft_alloc_buffer_n_default: failed to allocate CUDA0 buffer of size 3792084992
```

放 CPU 同样不行：内存提交已到 27.4 / 27.8 GB（页面文件仅 12 GB）

```
OSError: 页面文件太小，无法完成操作。 (os error 1455)
```

## 3. 试过的方案：转 GGUF 交给 Ollama（不可行）

```powershell
ollama create qwen35-clean -f Modelfile --force
# importing safetensors model → successfully imported qwen35-clean with 480 layers（1.7 GB）
ollama run qwen35-clean "ＺＸ－１２００　巡检周期？？？"
# Error: MLX runtime is not available: failed to load MLX dynamic library
```

**转换成功、推理失败**：Ollama 0.40.16 对 `qwen3_5` 架构（混合线性注意力 + 视觉塔）只提供 MLX 后端，
Windows 上没有 MLX，所以跑不起来。这是 Ollama 的运行时限制，不是转换问题。

## 4. 可行方案：embedding 挪到 CPU，GPU 全给清洗模型

Ollama 支持给单个模型指定 `num_gpu 0`：

```powershell
# 1) 造一个只跑 CPU 的 embedding 模型
@'
FROM bge-m3
PARAMETER num_gpu 0
'@ | Set-Content Modelfile.bgem3cpu
ollama create bge-m3-cpu -f Modelfile.bgem3cpu

# 2) 后端指向它
# .env
OLLAMA_EMBEDDING_MODEL=bge-m3-cpu

# 3) 清洗服务正常用 GPU 起
cd llmops-backend
.\.venv\Scripts\python.exe tools\clean_server.py --model "D:\models\Qwen3.5-0.8B-TextPreprocessor" --port 8010
```

### 向量一致性验证（关键）

担心换设备导致向量漂移，实测两个模型对同一文本的输出：

```
注塑机 ZX-1200 巡检周期   cos=1.000000  maxdiff=2.36e-03
受限空间气体检测要求       cos=1.000000  maxdiff=0.00e+00
```

**完全一致**（同一份权重，只是计算设备不同）。历史 Chroma 索引不需要重建。

### 实测性能（两者同时在线）

| 阶段 | 耗时 |
|---|---|
| 输入清洗（GPU，模型通道） | 275–594 ms |
| 检索（CPU embedding） | 68 ms（热）/ 1069 ms（冷） |
| 精排（云端） | 361–475 ms |
| 端到端 | 2.6–3.1 s |

GPU 占用 2.6 GB（清洗模型），CPU embedding 不占显存，互不干扰。

## 6. 回滚

```ini
# .env 改回
OLLAMA_EMBEDDING_MODEL=bge-m3        # 或删掉这行
```

然后停掉 8010，重启后端即可回到「embedding 用 GPU、清洗用规则通道」的状态。

## 7. 两个开关别混淆

| 开关 | 位置 | 作用 |
|---|---|---|
| `INPUT_CLEAN_MODE` | `.env` | 服务端默认通道：`off` / `rule` / `model` |
| 「输入清洗」 | 前端 | 本次请求是否清洗 |
| 「精细清洗」 | 前端 | 本次请求是否升级到模型通道 |

服务端 `off` 时，前端两个开关仍可临时启用模型通道（当前就是这种用法）。
