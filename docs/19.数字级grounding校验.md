# 数字级 grounding 校验

- 日期：2026-11-17
- 前置：docs/18（30 题端到端评测 96.7%，唯一失败是把"额定载重"答成"模具重量上限"）
- 结论：生成后加了一道**数字来源校验**；它挡"编数字"，不挡"答错属性"

## 1. 做了什么

新增 `app/services/grounding.py`，两条路径（`chat()` 与 `stream()`）生成完成后统一过一遍：

1. 从回答里抽数字（**≥2 位或带小数点**，个位数与列表序号噪音太大，不校验）；
2. 剔除 `【依据：知识片段N】` 里的编号（那是引用下标，不是事实数值）；
3. 每个数字都必须在**喂进去的片段原文**（含标题）里出现过——千分位归一（`1,000` ≡ `1000`）；
4. 有缺失就在回答末尾追加提示，并在 `done.grounding` 里记下 `{ok, numbers, missing}`。

配置：

```ini
RAG_NUMERIC_GUARD_ENABLED=true
RAG_NUMERIC_GUARD_TEXT=（提示：回答中的 {nums} 未在知识库片段中找到依据，请核实。）
```

流式场景无法撤回已吐出的 token，所以做法是**追加一段 delta 提示**，同时 `done.answer` 带上提示文本、`done.grounding.ok=false`，前端可以据此标黄。

## 2. 它确实能挡住历史上那个幻觉

拿 docs/16 §5 里模型编出来的那条答案回放：

```
输入：ZX-1200 型号的注塑机模具重量上限通常为 1,000 公斤。建议在实际操作中进行测试以确保安全性。
片段：…锁模力 1200 千牛，螺杆直径 36 毫米，液压油滤芯每 400 小时一次…
校验：{'ok': False, 'numbers': ['1200', '1000'], 'missing': ['1000']}
```

正常答案不受影响：

```
输入：注塑机 ZX-1200 的锁模力是 1200 千牛【依据：知识片段1】。
校验：{'ok': True, 'numbers': ['1200', '1200'], 'missing': []}
```

## 3. 但它在 30 题上一次都没触发

用新代码重跑 30 题端到端评测：结果与加校验前完全一致（96.7%，逐题判定相同），**触发次数 0**。

原因不复杂：docs/17 的严格提示词 + 无命中固定话术已经把"凭空编数值"这条路堵住了——要么拒答，要么有片段依据。所以这道闸目前是**兜底护栏**，不是主力。

真正需要它的是另一种场景：检索命中了、模型也在片段范围内说话，但顺手补了一个片段里没有的数（比如把"高温段"补成"不超过 300 度"）。本批 30 题没构造出这种样本。

## 4. 它挡不住什么（重要）

`docs/18` 的 E13：

> 皮带输送线 CV-120 的模具重量上限是每米 50 千克【依据：知识片段1】。

片段原文是"额定载重 50 千克每米"——**50 这个数字确实在片段里**，所以数字校验放行。这是**属性错配**，不是数字伪造。

两类错误的区别：

| 类型 | 例子 | 数字校验 | 需要什么 |
| --- | --- | --- | --- |
| 数值伪造 | 编出"1,000 公斤" | ✅ 拦得住 | — |
| 属性错配 | 把"载重"当"模具重量上限" | ❌ 拦不住 | 属性词级校验（回答里的属性词是否出现在片段中） |

要堵 E13，得做**属性级**校验：从回答里解析出"X 是 Y"的 X（属性名），要求 X 的字符片段或近义表述也出现在引用片段里。这比数字校验难得多（同义词、缩写、"容量"vs"额定容量"），本次没做。

## 6. 现状与下一步

四层拒答链路已经闭环：

```
检索闸门 0.92 → 严格提示词 → 无命中固定话术 → 数字校验
```

30 题口径 96.7%，剩 1 例（E13，属性错配）。

下一步按性价比：

1. **属性级校验**（半天到一天）：堵 E13 这类"有依据但答错属性"，可以先做简单版——回答里"的 X 是/为"的 X，要求至少在片段里出现一次字符重叠 ≥ 4 字的片段。
2. **扩充题库到 60–80 题**，补"过期数值""近义属性"两类。
3. 换更强生成模型复跑，区分"策略问题"与"模型能力问题"。
