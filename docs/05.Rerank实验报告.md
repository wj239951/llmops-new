# 05. Rerank 精排实验报告

> 目标：在 [docs/04.评测报告](04.评测报告.md) 的 cosine 检索基线上，验证「bge-m3 宽召回 + bge-reranker-v2-m3 精排」两级检索能否解决「无答案问题被强行放行」的问题，并给出可复现的阈值标定。

## 1. 背景：cosine 单阈值为什么不够

docs/04 的 45 题实测结论：

- 正确题 top1 cosine 最低 **0.5808**，中位数 0.6641；
- 无答案题 top1 cosine 最高 **0.6790**，均值 0.5954；
- 两组分数重叠区间 **[0.5808, 0.6790]**，`threshold=0.53` 时 8 条无答案问题 **100% 被放行**；扫描全部阈值也找不到同时满足「hit ≥ 85% 且误接受 ≤ 20%」的点。

根因是双塔向量只衡量「整段文本主题是否相似」，无法判断「这段文字是否真的回答了这个问题」。精排层换成交叉编码器：把 query 与候选片段拼在一起做一次完整编码，直接输出相关性分数。

## 2. 方案与实现

### 2.1 两级检索流程

```
用户问题
  │
  ▼
bge-m3 余弦召回 K 条候选（RAG_RERANK_CANDIDATE_K）
  │
  ▼
bge-reranker-v2-m3 对 (query, chunk) 逐对打分 → sigmoid ∈ (0,1)
  │
  ▼
精排阈值过滤（RAG_RERANK_SCORE_THRESHOLD）
  │
  ▼
截断 RAG_FEED_TOPK 条 → 拼上下文 → 对话模型
```

### 2.2 设计取舍

- **默认关闭**（`RAG_RERANK_ENABLED=false`）：torch + 2.17GB 权重不是所有部署都需要；不装依赖不影响主链路。
- **自动回退**：开启但依赖/权重缺失时，`RAGService.search` 回退纯 cosine 并打 warning，服务不崩、不影响启动。
- **精排阈值独立**：精排分数是 sigmoid(logit)，与 cosine 不同尺度，不能复用 0.53/0.06；单独提供 `RAG_RERANK_SCORE_THRESHOLD` / `RAG_RERANK_WEAK_MARGIN`。
- **候选池与截断分离**：先精排全部候选、再按阈值过滤、最后截断，避免「先截断后过滤」丢掉第 4 名之后过线的片段。
- **打分方式自适应**：`ChatService` 通过 `RAGService.active_score_config()` 取当前生效的（阈值, 余量, 打分方式）决定 `rag_status`，日志里会写 `打分=rerank`。

### 2.3 代码与配置

| 位置 | 内容 |
| --- | --- |
| `app/services/rerank_service.py` | `CrossEncoderReranker` 懒加载单例、线程安全 `load()`、批量 `score()`、`rerank_chunks()`；`is_available()` 失败只尝试一次 |
| `app/services/rag_service.py` | `search()` 两级检索 + 异常回退；`active_score_config()` |
| `app/services/chat_service.py` | `rag_status` 按当前打分方式取阈值；日志输出 `打分=rerank/cosine` |
| `app/core/config.py` | `RAG_RERANK_ENABLED / MODEL / MODEL_PATH / CANDIDATE_K / SCORE_THRESHOLD / WEAK_MARGIN / MAX_LENGTH / DEVICE` |
| `tools/evaluate_rerank.py` | 精排评测：recall@K、MRR、hit@3、top1、无答案误接受、延迟、阈值/余量扫描，并读 docs/04 基线做对照 |
| `tests/test_rerank.py` | 4 个用例：精排重排+阈值过滤、模型不可用回退 cosine、`active_score_config` 两种模式 |

### 2.4 实验环境

- Windows 本机，`llmops-backend/.venv`，Python 3.14.6
- `torch 2.15.0+cpu`、`transformers 5.22.1`（PyPI Windows CPU wheel，未启用 CUDA）
- 权重 `D:\models\bge-reranker-v2-m3`（`model.safetensors` 2.17GB），`device=cpu`
- 向量化与基线同 docs/04：Ollama `bge-m3`、Chroma `knowledge_bge_m3`、21 条向量

## 3. 实验设置

- 题库：`experiments/eval_qa.jsonl`，45 条（37 可回答 = 21 exact + 16 paraphrase；8 无答案 = 4 远域 + 4 近域）
- 指标：recall@K、MRR、coverage / hit@3 / top1 准确率、无答案误接受（far / near / all）、单次精排耗时
- 候选池 **K=6**（与 cosine 召回池相同）。另跑过 K=12：结果逐题分数与指标完全一致，但 CPU 精排耗时约为 2.4 倍（10.35s vs 4.30s），因此部署默认取 6。
- 评测口径：严格复刻线上 `RAGService.search()`（召回 → 精排 → 阈值过滤 → 截断），不改线上代码。

## 4. 结果

### 4.1 总体指标

| 指标 | cosine 基线 (t=0.53) | rerank t=0.50 | **rerank t=0.76（部署值）** |
| --- | --- | --- | --- |
| recall@K | 100% | 100% | **100%** |
| MRR | 1.0000 | 1.0000 | **1.0000** |
| coverage（有片段喂给模型） | 100% | 97.3% | **97.3%**（36/37） |
| hit@3（正确片段进入 top3） | 100% | 97.3% | **97.3%** |
| top1 准确率（喂入片段） | 100% | 97.3% | **97.3%**（among fed 100%） |
| 无答案误接受 far / near / all | 100% / 100% / 100% | 0% / 50% / 25% | **0% / 0% / 0%** |
| 单次精排耗时（K=6, CPU） | — | 4.30s（max 5.08s） | 4.77s（max 6.19s） |

要点：

- 精排把 8 条无答案问题从「全部放行」变成 **t=0.76 时 8/8 全部拒掉**；
- 代价是 **1/37 漏答**（q02，改写题），coverage 从 100% 降到 97.3%；
- 首次请求需 13–16s 加载模型（进程级单例，之后复用）。

### 4.2 分数分布

| 组 | 最低 | 中位数 | 均值 | 最高 |
| --- | --- | --- | --- | --- |
| 可回答题 top1 | 0.2368（q02，漏答） | 0.9837 | 0.9422 | 0.9998 |
| 无答案题 top1 | 0.0010（q38） | — | 0.2680 | 0.7509（q43） |

剔除 q02 后，可回答题 top1 最低 0.7817（q37）；无答案题最高 0.7509（q43）。**正确与错误的间隔只有 0.0308**——精排把重叠从「1:1 不可分」压缩到「0.03 的窄缝」，但仍不是天然可分。

### 4.3 阈值扫描（0.05–0.95，步长 0.01）

| 区间 | coverage | 无答案误接受 | 说明 |
| --- | --- | --- | --- |
| 0.05–0.23 | 100% | 50% | 全部正确题保留，但无答案只拒掉 far |
| 0.24–0.26 | 97.3% | 50% | q02 开始被误杀 |
| 0.27–0.41 | 97.3% | 37.5% | 拒掉 q42 |
| 0.42–0.69 | 97.3% | 25% | 拒掉 q44，剩 q43/q45 |
| 0.70–0.75 | 97.3% | 12.5% | 只剩 q43 |
| **0.76–0.78** | **97.3%** | **0%** | **推荐 0.76（balanced accuracy 98.65%）** |
| 0.79–0.81 | 94.59% | 0% | 开始误杀正确题（q37=0.7817） |
| 0.82–0.83 | 91.89% | 0% | |
| 0.84–0.93 | 89.19%→86.49% | 0% | 继续误杀 |
| 0.94–0.95 | 83.78%→75.68% | 0% | |

阈值推荐来自扫描：**0.76** 是「误接受 0% 且 coverage 最高」的最小值；不丢任何正确片段的最大阈值是 0.23。可选稳定区间 [0.70, 0.93] 是脚本按 balanced accuracy 给的范围，但 0.70–0.75 仍有 12.5% 误接受，实际可用的「零误接受」平台只有 0.76–0.78。

> ⚠️ 0.76 距最高误接受样本（q43=0.7509）只有 **0.0091**，平台宽度仅 0.03。这是 45 条小样本上标定出的刀刃值，不能当常数——换语料/扩题库必须重扫。

### 4.4 误判明细

**漏答（1 条）**

- **q02**（paraphrase）「这个平台本地版用什么模型来跑对话？」
  - cosine 正确召回 doc44 且排第 1（0.5814），但精排只给 **0.2368** → 被 0.76 过滤；
  - 人工对照：同一事实的不同写法「本地部署时，对话模型由 Ollama 提供，默认模型是 deepseek-r1:7b。」→ **0.9628**；原文句「本地版使用 Ollama 运行 deepseek-R1:7b，云端使用 DeepSeek API。」→ **0.1873**；简化问句「本地版用什么模型跑对话？」→ **0.4708**。
  - 结论：这是精排模型对「跑对话 / 运行」等口语化表述的**真实缺陷**，不是脚本 bug；也说明单条合成题会放大模型偏好。

**误接受（t=0.76 时 0 条；在低阈值下的明细）**

| id | 类型 | 问题 | 精排分 |
| --- | --- | --- | --- |
| q38 | far | 公司员工每年有多少天带薪年假？ | 0.0010 |
| q39 | far | 叉车驾驶员需要持什么证上岗？ | 0.0044 |
| q40 | far | 厂区废水排放的 COD 限值是多少？ | 0.0067 |
| q41 | far | 公司 IT 服务器的数据备份周期是多久？ | 0.0056 |
| q42 | near | 食堂从业人员健康证的有效期是几年？ | 0.2618 |
| q43 | near | 注塑机 E-073 错误码对应的模具温度传感器型号是什么？ | 0.7509 |
| q44 | near | 空压机 GA-90 变频器的载波频率应设置多少？ | 0.4196 |
| q45 | near | 干粉灭火器出厂满几年必须报废？ | 0.6942 |

远域问题精排分几乎为 0（0.001–0.007），一次拉开；**近域问题才是难点**（0.26–0.75），q43 更是紧贴阈值。

### 4.5 弱命中余量（margin）

- 题库中**没有「top1 错误但过阈值」的样本**（过阈值即正确），因此 margin 无法标定，`rerank_summary.json` 里为 `null`；
- 保留与 cosine 一致的 0.06：在 t=0.76 下会把 2/36 正确命中降级为 `weak_hit`（**5.56%**）——q37=0.7817、q10=0.8157，判定线 0.82；
- 余量要等更大题库出现错误 top1 样本后再标，当前不宣称 0.06 有依据。

## 5. 与 cosine 基线的取舍

| | cosine | rerank（t=0.76） |
| --- | --- | --- |
| 无答案误接受 | 100%（8/8） | **0%**（0/8） |
| 可回答覆盖率 | 100%（37/37） | 97.3%（36/37） |
| 单次检索延迟 | ~0s | +4.3–6.2s（CPU，K=6） |
| 首次请求 | — | +13–16s 模型加载 |
| 部署复杂度 | 只依赖 bge-m3 | 额外 torch/transformers + 2.17GB 权重 |

结论：精排在本语料上把「拒答能力」从 0 变成可用，代价可控（1 条漏答 + CPU 延迟），值得作为**可选层**接入；本仓库默认关闭、`.env` 一键开启。是否默认开启取决于业务对「宁可拒答 vs 宁可多答」的偏好。

## 7. 局限与下一步

1. **小样本**：45 条、11 篇语料、8 条无答案；0.76 是刀刃值（距 q43 仅 0.009）。需扩到 150+ 条、跨语料验证，不能直接搬阈值。
2. **改写题漏答**：q02 显示精排对口语化改写敏感，可按错误类型补数据，或对「问题-片段」加指令式前缀再试。
3. **CPU 延迟**：K=6 时 +4.3–6.2s/次，未启用 CUDA/ONNX 加速；生产可通过 GPU、ONNX Runtime 或更小 reranker（bge-reranker-base）优化。
4. **只评检索层**：端到端「模型是否拒答」尚未评测；RAG 提示词仍允许模型在知识不足时结合通用知识补充，`no_hit` 不等于最终回答一定说「不知道」。
5. **余量不可标定**：当前无错误 top1 样本，`weak_hit` 余量沿用 0.06 仅保持行为一致。

## 9. 补遗：云端精排标定（2026-11-12，2核2G 服务器）

本地权重在 2核2G 服务器上跑不动，精排切云端（`RAG_RERANK_PROVIDER=cloud`，SiliconFlow 托管同模型 `BAAI/bge-reranker-v2-m3`）后按同一套 45 题重标。与正文口径的差异：候选池跟生产配置走混合 RRF（服务器 `RAG_HYBRID_ENABLED=true`），`tools/evaluate_rerank.py` 已改为 provider / 候选池均跟生产配置，并对云端瞬时 400（SiliconFlow 20015，实测偶发）整题重试 3 次。

**结果（阈值 0.76）**：recall@6 100%、MRR 1.000、hit@3 97.3%（36/37，漏的仍是 q02 改写题）、误接受 0/8；单条精排均值 260ms（本地 CPU 为 4.3–6.2s）。

**分数可分离性**：无答案 top1 最高 0.743（q43）；正确命中 top1 最低 0.2408（即漏答的 q02），其余正确命中 ≥0.77。与本地相比尺度接近但分离余量更大：0.76 距最高误接受 0.017（本地 0.009）。

**阈值扫描结论**：零误接受且命中最大的窗口为 **[0.75, 0.77]**（hit 97.3%）；≥0.78 开始丢正确片段（0.78 时 94.6%），≥0.95 命中跌到 75.7%。**0.76 落在窗口中间，沿用原值，服务器 `.env` 无需改**。

**余量**：与正文第 7 节同况——已喂片段中无错误 top1 样本，余量不可标定，沿用 0.06；代价是 2 条正确命中（top1 约 0.77x / 0.8x）被降级为 weak_hit 显示。

产物：`experiments/results/calib_cloud/`（per_query / threshold_sweep / margin_sweep / summary）。

## 10. 补遗：复合问句查询分解（2026-11-12，服务器）

**问题**：「驾驶公务车辆出差怎么报销，有什么制度」跨两篇文档，交叉编码器按 (整句, 单片段) 打分仅 0.60，被 0.76 闸门全滤 → 零召回。降全局阈值无解：0.60 低于无答案题 q43 的 0.743，降阈值会破拒答。

**方案**：`app/services/query_decompose.py`，精排前用 deepseek-chat 把复合问题拆成 1–3 个主题子问句，各自召回 + 精排 + 过闸，按 (doc_id, chunk) 去重保留最高分，降序喂 top-3；单主题问题原样直通；分解/解析/模型任何失败回退 [原句]。开关 `RAG_QUERY_DECOMPOSE_ENABLED`（默认 false），每问多一次 LLM 调用。

**关键实测**：

| 问句 | top1 精排分 |
| --- | --- |
| 驾驶公务车辆出差怎么报销，有什么制度（整句） | 0.6032 ✗ |
| 驾驶公务车辆出差怎么报销（按标点拆，仍复合） | 0.3999 ✗ |
| 差旅费用报销有什么制度规定（主题归一） | 0.9629 ✓ |
| 公务车辆派遣管理有什么制度（主题归一） | 0.9542 ✓ |

两个坑：① 按标点机械拆不行，前半句仍是复合句；② 提示词只写「归一成正式主题表述」的纯指令会被模型忽略（实测仍照抄标点拆分结果），必须带少样本示例锚定行为。单主题直通保持阈值标定尺度不变。

**回归（生产 search，分解开启）**：hit@3 36/37 = 97.3%（与基线一致，漏的仍是 q02 改写题）、误接受 0/8，45 题 63s。复合问句端到端返回 3 条来源（0.963 / 0.893 / 0.87，doc 53/55），拒答闸门未破。

**部署**：服务器 `.env` 增 `RAG_QUERY_DECOMPOSE_ENABLED=true` 与 `DEFAULT_MODEL_PROVIDER=deepseek`（前端聊天显式传 provider，但分解层走默认值，服务器无 Ollama 必须补）。测试：`tests/test_query_decompose.py` 12 例（mock LLM + search 合并/去重/闸门集成），`pytest` 73 passed。
